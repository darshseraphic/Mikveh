## Ways to help without modifying the Software

- Report a reproducible bug or incorrect behavior.
- Suggest an accessibility, usability, or documentation improvement.
- Report a broken installation step or a Chrome compatibility issue.
- Describe an API response or reference that does not behave as expected.
- Review the public documentation and point out unclear or outdated instructions.

Submitting feedback does not grant permission to modify or redistribute the Software.

## Reporting an issue or suggesting an improvement

1. Read the [README](README.md) to understand the current features and limitations.
2. Check the existing issues or discussions, if enabled, to avoid duplicates.
3. Provide a concise description of the issue or proposed improvement.
4. For a reference-search issue, include the exact input (for example, `Luke 1:37`), the expected behavior, the observed behavior, and whether the random-verse request works.
5. For a visual issue, include the Mikveh version, Chrome version, operating system, theme setting, and a screenshot where useful.
6. Remove passwords, personal details, private messages, and other sensitive information from reports.

## If written permission is granted

If the copyright holder expressly authorizes a code or documentation contribution in writing, follow the scope and conditions of that permission. The authorization should identify what may be changed and whether the proposed material may be included in the project. Keep any authorized contribution focused and document new permissions, dependencies, storage, or network behavior.

Do not assume that opening an issue, sending a suggestion, or receiving a general acknowledgement gives permission to modify the Software.

## Security issues

Please do not publish exploitable vulnerability details in a public issue before the maintainer has had a reasonable opportunity to investigate. Follow [SECURITY.md](SECURITY.md) for reporting guidance.

## Third-party material

Do not submit third-party code, images, fonts, translations, or documentation unless their terms are known and the copyright holder has approved their inclusion. Preserve required notices and attribution. The current project uses bible-api.com to retrieve WEB verse data; API service terms and Bible text notices are separate from the Mikveh license.
